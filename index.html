核心演示

用日常的话问一句，看三段接力怎么跑完

下面这一段是真的能跑的。选择你的校区，像发微信一样提问，三段输出会依次生成，最后由理小办收口成一张办事卡。

支持 Enter 运行（Ctrl/⌘+Enter 换行）

    创意思路

    为什么是「三段接力」，而不是一个什么都会的机器人

    关键不在能力大小，而在职责边界。单一智能体既查又排又填，容易产出无依据的臆测和自相矛盾的步骤；分离之后，每一环都能单独校准，也便于横向复用。

    ①

    信息智能体

    查得准
    唯一职责
    在指定检索域内定位条款，输出带出处的原始事实片段
    交付物
    「事实 + 出处 + 适用校区 + 更新时间」的清单
    明确不做
    不下结论、不给建议、不臆测；检索域按场景收窄，不混入无关规章
    ②

    规划智能体

    排得顺
    唯一职责
    基于事实判断先后依赖与条件分支，拆成可逐条执行的步骤
    交付物
    有序步骤序列，分支显式写出
    明确不做
    不查原始规定、不填地点材料、不修改事实结论
    ③

    执行助手

    做得成
    唯一职责
    为每一步补齐「入口 / 地点 / 材料 / 注意事项」四要素
    交付物
    每步四个字段全部落地，缺一项学生就可能白跑一趟
    明确不做
    不重排步骤、不改结论、不自行判断分支
    唯一答案原则。三路结果由「理小办」统一收口成一张办事卡，遵循结论先行 · 步骤可执行 · 依据可追溯——只给一个答案，不给三个让学生自己拼的答案。

    四要素的合格 / 不合格对照

    要素合格不合格
    入口i大工 APP → 玉兰卡 → 卡片挂失登录校园门户自行查找
    地点凌水：网信中心一楼服务大厅（东门），周一至周五 08:00–15:00校园卡服务大厅（不说校区差异）
    材料本人身份证原件，需本人到场相关证件
    注意补卡 25 元/次；初始密码未改不可自助解挂，须到服务大厅注意保管好证件

    缺入口 → 不知道从哪进；缺地点 → 跑错校区；缺材料 → 到了窗口被退回；缺注意 → 以为能自助，到了才发现必须本人到场。

    复用性

    换三样东西，换一个场景

    架构与输出格式完全不变，迁移到新场景只替换三处配置。这也是「理小办」真正的价值：一套校务智能体生产方法，规则只维护一处。

    换

    检索域

    把信息智能体的知识范围从「学生证件」换成「住宿与后勤维修」等对应规章。

    坑：检索域必须按校区与问题类型切分，不切分就会给出跑错校区的答案。
    换

    执行字段

    四要素模板不变，只替换入口、地点、材料、注意事项的取值。

    坑：同一句「坏了」可能对应 4 个不同渠道，必须先分诊再给入口。
    换

    真实问法

    用学生实际会说的话作触发语料，覆盖同义、模糊、情绪化表达。

    坑：学生不会说「设施设备报修申请」，只会说「寝室东西坏了」。语料里没有这些说法，智能体就永远接不到真实提问。

    未核实项清单：这类字段我们宁可留空

    下方清单来自各场景配置里的 待核实 项。按数据纪律，未核实的字段不得凭推测填入办事卡，所以它们在卡片里会显式显示为【待核实】。

    应用效果

    把规则只维护一处

    过去

    自己拼凑路径

    翻公众号推文、找学院通知、问同学 → 自己猜顺序 → 跑一趟窗口 → 漏带材料或走错网点 → 二次往返

    →
    现在

    直接照做

    一句话提问 → 拿到包含入口、地点、材料、注意事项的办事卡 → 材料备齐一次办成，并可就任一步继续追问

    对学生路径由「自己拼凑」变为「直接照做」，拿卡即可动身
    对部门不必反复解释同一件事，规则变更只需维护一处
    对学校形成可复用的「校务智能体」生产方法，新场景三步配置即可上线

    关于

    数据来源与合规声明

    这是一个原型站点

    界面为可运行的功能原型，标注为原型线框风格，不伪造真实截图或真实对话记录。演示中的答复由内置规则引擎在下方依据库上推演，不代表学校官方口径。

    依据可追溯

    每条事实都带出处。办事卡底部会列出全部依据文件，并对处于草稿状态的场景显式标注【待核实】，未核实字段一律留白，不以推测填补。

    不虚构效果

    未实测的效果数据一律保留【待填】占位；引用的规定名称、地点、费用、时限需在上线前核对至最新版本。

    检索域有边界

    遇到检索域外的问题，智能体会明确回答「未覆盖」并给出可选方向，而不是生成一个看起来合理的答案。这是「信息智能体」职责边界的直接体现。
